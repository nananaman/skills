# Excalidraw で作図する

公式 [`@excalidraw/cli`](https://github.com/excalidraw/cli) を使う個人用の作図手順。Excalidraw が配布する公式 skill ではない。
成果物は編集可能な `.excalidraw` と、その scene を CLI で描画した PNG。PNG だけの画像生成や加工で代替しない。

## 根拠と範囲

- コード由来の図は対象コード・関連文書を読み、リポジトリ、commit、参照ファイルを記録する。未コミット差分が根拠に含まれる場合も明記する。
- 実装で確認した境界・主要データ・方向を描く。設計案や未確認の依存は区別し、凡例で意味を示す。static code / manifest の確認を実デプロイの確認とは扱わない。
- 提供された説明からの図では、その説明を根拠にし、勝手にサービスや保存先を補わない。
- シークレット、認証情報、個人情報、実会話内容を図に含めない。作図のために対象コード・Git状態・インフラを変更したり、対象アプリや検証環境を起動したりしない。

## CLI を確認する

`excalidraw --version` と `excalidraw render --help` で利用可能な版・オプションを確認する。必要に応じて公式 README と照合する。
ローカル描画には Node.js 22 以上と、既存の Chrome / Edge / Chromium / Firefox が必要。CLI はブラウザをダウンロードしない。未検出なら実在する binary を `--browser-path` で指定する。

この環境の CLI pin は dotfiles の `home/.config/mise/config.toml` にある `npm:@excalidraw/cli`。CLI が未導入なら、依頼の許可範囲で管理された版を導入する。ホストへの適用が依頼範囲にない場合は、作業ディレクトリ内の一時導入で確認する。単に作図するために pin やグローバル設定を更新しない。

`render` はローカル実行であり、アカウントや API キーを要求しない。Excalidraw+ の login、scene upload、外部共有は作図依頼から推測しない。

## 読み筋と配置を決める

要素を並べる前に、読み手が最初に理解すべき関係と、その後に追う主経路を決める。タイトル、責任境界、主要ノード、補足の順に情報の強弱を付け、注記を主経路と競合させない。

- 構成・データフロー図は責任境界ごとにまとめ、主要な流れを一方向に揃える。往復・非同期・観測の線は別の通り道へ逃がし、交差を減らす。境界をまたぐ必要な線は保持する。
- シーケンス図は登場者の列を揃え、時間を上から下へ進める。排他的な分岐は排他性を示し、共通へ戻る処理がある場合は合流位置を示す。終了する枝や並行処理は、その意味を保つ。状態遷移図では戻り線を外側へ回し、遷移条件を対応する矢印の近くに置く。
- ノードの大きさ、列・段の位置、内側の余白を揃える。長い日本語は意味の切れ目で改行し、文字を小さくして押し込む前に箱や列間を広げる。要求された文言や条件は省略しない。
- 色は境界や役割の区別に絞り、同じ意味に同じ色・線種を使う。主経路は十分なコントラスト、注記や補助線は控えめにし、色だけに意味を担わせない。飾りの図形や線で情報量を増やさない。

既存図の修正では元の読み筋と配色を尊重し、依頼範囲の要素とその配置を調整する。新規図のための配置方針を、無関係な要素の再配置に使わない。

## 編集可能な scene を作る

新規図は Excalidraw の scene JSON を作成する。CLI の `render` は既存 scene の描画機能であり、未提供の作図コマンドを仮定しない。
既存図では要素 ID を保ち、依頼された内容・スタイルだけを変える。文字・ノード・主要な矢印はそれぞれ編集できる要素にする。

ユーザーの指定がなければ、手描きの見た目を既定にする。

- 線は `roughness: 1`、塗りは淡色の `fillStyle: "hachure"`。境界と主要経路を区別できる配色にする。
- 文字は `fontFamily: 5`（Excalifont）。日本語を含む CJK は公式レンダラーの Xiaolai fallback に対応する。本文と注記は縮小表示でも判読できる大きさにする。
- 矢印のラベルが線やハッチに重なる場合は、ラベル下を不透明な塗りにする。背景は必要な文字周りに絞り、他のノード・境界の枠や見出し、矢じりを隠さない位置に置く。矢印中央にラベルを置く場合も、前後の経路と方向を追える線を残す。
- 経路が見出しや長いラベルを横切らない余白を取り、矢印の方向、凡例、境界を保つ。見た目のために依存やデータフローを変えない。

## 日本語フォントとローカル描画

手描きの CJK フォントは初回に取得・キャッシュされる。ネットワークが使えない場合や `--fonts-url none` 指定時、未キャッシュの文字はシステムフォントへ fallback する。日本語が表示されたことだけで、手描きフォントの適用成功とは判断しない。
必要なフォントの取得、CLI の警告、PNG の実際の文字を確認する。キャッシュ前提を含む再描画条件や、fallback に残った制約を報告する。scene や会話データをフォント配信先へアップロードする必要はない。

例（必要に応じてサイズ・scale を調整）:

```sh
EXCALIDRAW_NO_UPDATE_NOTIFIER=1 excalidraw render diagram.excalidraw \
  --out diagram.png --scale 2 --max-width 6000 --max-height 4400
```

ブラウザは描画用の一時プロファイルで起動する。CLI が起動に失敗した場合は browser の実在・実行権限とエラーを確認し、環境の許可範囲で再試行する。対象アプリの起動で代替しない。

## PNG の確認と受け渡し

生成した PNG を実際に開く。全体では情報の階層・整列・余白を見て、主経路を始点から終点まで追う。必要な拡大部分で日本語の欠け、文字の切れ・重なり、矢じりとラベルの対応、背景による別の枠や線の遮蔽を確認する。
読みにくい箇所はsceneの位置・折返し・経路・背景を修正し、CLIで再描画して確認する。変更した箇所だけでなく、隣のラベルや境界、戻り線にも新しい干渉がないか見る。意味と依頼範囲を保ち、主経路と条件を迷わず追えることを完成の基準にする。成功したrenderの終了コードだけではvisual QA完了にしない。

編集用 scene、PNG、根拠一覧（コード由来なら repo / commit / 参照ファイル）をユーザーが受け取れる形で渡す。利用可能な正式ファイル出力・保存手段を使い、既存アイテムの更新依頼では同じ ID の新バージョンを確認する。未確認事項と保存できなかった制約は区別して報告する。
