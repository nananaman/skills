# 証拠から失敗と変更先をつなぐ

本文は、一次振り返りで問題があった場合や、候補が出ない・比較が同点に偏る場合に使う。取得元・権限・予算は[取得手順](read.md)と今回の依頼に従う。新しいパスの探索許可や、元実務の再開を意味しない。

## 抽出と提案を分ける

取得できた本文を読み、先に出来事を並べる。依頼・失敗直前の状態、操作、応答、訂正・再編集、回復、最後の状態を対応付ける。その後で現在のskill・設定と照合し、どの判断が変われば防げるかを考える。候補を先に決めて都合のよいエラーを集めない。

出来事ごとに、出典の参照、直接観測か自己申告か、因果関係の確度を付ける。親子・同一実務の再返信を重複計上しない。非ゼロ終了、再編集回数、tool呼出数だけで品質や原因を決めない。少なくとも次を区別し、分からないものは未分類にする。

- 手戻り：期待した契約や条件を見落とし、後からやり直した。
- 不要な再試行：既存結果や拒否対象を確認せず同じ操作を重ねた。
- 対象外書込み：承認・作業範囲を越えた実行。拒否され未実行の要求と分ける。
- 正常な保留：承認待ち、不確かな実行結果の確認、後続の中止を守った停止。
- 期待した失敗：意図した振る舞いを確かめるTDDのRed等。構文・コンパイル・環境エラーを代用しない。

各出来事を「現在の指示の不足」「指示はあるが起動・適用されなかった」「知識・tool・環境差」「評価器が見逃した」「原因不明」等へ仮置きし、反証も残す。記述が既にあることだけで変更不要にしない。起動を直す、検査へ移す、不要な工程を削る、参照を必要時だけ読む方法も比較する。

## 取得済みexportの索引

許可された `session_reader.py` のexportだけを `scripts/evidence_index.py` へ渡せる。自動探索・元ログの追加取得・state更新はしない。Workの自己申告は別入力として指定する。POSIXのPythonで使用し、パスはsymlinkを含まない正規パス、出力は全Git checkoutの外の新しい本人限定ディレクトリにする。出力先の親は事前に存在する必要がある。

```sh
python3 scripts/evidence_index.py \
  --export /private/authorized-reader-export.jsonl \
  --self-report /private/collected-reflection.md \
  --repo /path/to/managed-skills --output /private/new-evidence-index
```

索引は本文・tool引数・応答本文を複写せず、入力SHAと行番号、明示的な `exit_code` / `isError`、user入力の位置を記録する。対応しない応答形式はunknown。user入力を自動で訂正扱いしない。取得元の正当性や、skillの実起動、原因はこの処理だけでは分からない。

精読後に `--annotations` でJSONを渡せる。キーは索引の `ref`、値は `{"labels":["rework"],"reason":"判断と根拠の短い説明"}`。ラベルは `rework` / `unnecessary_retry` / `out_of_scope_write` / `normal_hold` / `expected_failure`。一つの実務を複数事例に増やす集計ではない。自己申告の参照は `<SHA>:document` で、ラベルを付けても直接観測へ昇格しない。理由にも秘密や生ログを写さない。

`summary.json` と `events.jsonl` は私的な分析資料。`indexed` は処理終了であり、精読・取得範囲の完全性・改善済みの証明ではない。tool結果がない場合は `tool_result_evidence: unavailable` とし、結果件数はnull。自己申告だけの入力を失敗0件の実績にしない。`full_context_read_verified` は常にfalseで、精読状況は元の取得記録に残す。壊れた行、空のexport、読取り中の入力変化、対応しないannotation参照があればpartial・終了コード1。annotationもSHAと版変化を記録する。重複内容、symlink、既存出力、Git内出力等は終了コード2で停止する。途中のIOエラーでは未完成のディレクトリが残り得るため、再開時に新しい出力先を使い、完成扱いしない。

索引は調べる位置の補助であり、全文の振り返りを置換しない。元ログがないときは自己申告文書数だけを報告し、tool失敗件数を0件の実績として扱わない。未対応形式・未取得・元から省略された出力を別に残す。掲載には索引の内部参照を転記せず、必要な教訓と検証範囲だけを渡す。

## 既知の失敗で評価器を確かめる

改善候補へ進む前に、代表的な失敗を少数選び、失敗直前の依頼・ファイル・baseとhead・利用可能な指示・tool応答を固定する。症状が似た短い課題へ置き換えるときは、落とした条件と再構成であることを示す。解き方や新しい注意書きを依頼に足して再現を助けない。

成果と過程の両方を採点する。例えば途中で対象外生成物を削除して最後に戻す場合、最終diffだけでは見逃す。旧headだけ成功し統合先APIで失敗した場合、両方の状態を保つ。リンク配下へ書いた場合、最終ファイルの存在だけでなく書込み先の解決位置と元データも確認する。良い実行、正常な保留、期待したRedが誤検出されない対照も用意する。危険な実操作は保存済み証拠または使い捨ての模擬環境で検査し、拒否された本番操作を試験として再実行しない。

workbenchの `failure_replay` で対象check・出典・直前条件・再構成の有無を固定する。現行版がそのcheckに失敗しなければ、比較は「再現未確認」。同点を改善不要の証拠にしない。再構成で失敗を検出できても、元のモデル判断や実務の再発防止を実証したことにはならない。比較できない部分を保留し、他の独立した修正・検査を止めない。

## 日次結果を解釈する

既存のレポート・候補記録に、次の理由を区別して書く。採用件数を目標にしない。

- 新規問題なし：対象を読めた範囲と、既存の成功・反例を示す。
- 入力不足：本文なし、自己申告だけ、子task欠落、未対応形式など。問題なしに置換しない。
- 既出未解決：前回候補と不足条件を参照し、新しい根拠がある場合だけ再評価する。
- 候補の見送り・不採用：何を比較し、何が不足・悪化・重複したかを示す。未選定、再現未確認、評価不合格を分ける。

対象総数、本文を取得できた数、一次振り返り数、自己申告だけの数、問題・候補・選定・比較・採否を、数え方とともに返す。取得の上限と評価の上限を混ぜず、未分類や未計測をゼロで補わない。
