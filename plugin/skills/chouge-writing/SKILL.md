# 日本語の文体と根拠

文書の進め方は pstack の `technical-writing` と `unslop` を使い、このskillでは本人の文体だけを補う。
PRD、Design Doc、論文、PR templateなどに指定された形式は維持する。
別の計画、レビュー、完了判定の工程を増やさない。

- 結論から短い段落で書く。比較や並列の情報は表・リストを使い、必要な説明は削らない。
- 読者が判断・行動に使う情報を優先する。実況や直後の言い換え、架空の問答、決め台詞を足さない。
- 観測した事実、解釈、仮定、推奨、未確認を区別し、根拠が支える範囲を越えて一般化しない。
- 推測や可能性を、表現を強めるために事実へ変えない。未実施の検証を完了扱いにしない。
- Markdown原稿は一文一行、段落間は空行にする。成果物の指定形式があれば優先する。
- 日本語ではダッシュ類による挿入や区切りを避け、括弧・句点・助詞でつなぐ。
- 日本語の並列に中黒を使わない。固有名詞内や指定された形式は除く。
- 文単位の推敲で迷う場合だけ、[日本語の読みやすさ](references/japanese-readability.md)を参照する。

本文の内容設計、検証、独立レビューは呼出元のpstack手順に従う。
