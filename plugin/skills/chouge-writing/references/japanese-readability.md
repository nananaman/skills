# 日本語の読みやすさ

この reference は、構成と内容を固めた後、日本語の文と段落を推敲するときに使う。
自然に見せるために、意味、条件、不確実性、出所を変えてはいけない。

## 文の骨格を確認する

- 一文に一つの中心的な主張を置く。条件、例外、根拠が増えて読み手が戻る場合は文を分ける。
- 主語と述語を離しすぎない。修飾語や括弧が長くなるなら、先に対象を示すか文を分ける。
- 修飾語を、修飾される語の近くに置く。読点は意味の切れ目と係り受けが一致する位置に置く。
- 「これ」「それ」「このような」などの指示語は、指す対象が直前の一つに定まる場合だけ使う。離れた対象や複数候補を指すときは名称を繰り返す。
- 名詞を重ねた長い連体修飾を、必要なら動詞を使った文へほどく。名詞化で関係者、時点、因果が隠れていないか確認する。
- 受け身や「〜される」を使う場合は、行為者を隠す必要があるか確認する。誰が何をしたかが重要なら主語を出す。

「短い文」を作ることと、「読みやすい文」を作ることは同じではない。
前提条件や限定を削って短くするより、情報の関係を明示して読み手の負荷を下げる。

## 用語と具体性を整える

- 初出の用語は、読者に未知で、その後の理解に必要な場合に定義する。既知の略語の展開や和訳は重ねない。定義が長くなるなら例や図を使う。
- 同じものを別の呼び方で表さない。別のものを同じ上位語でまとめない。
- 抽象名詞だけで文を成立させず、可能な範囲で対象、動作、入力、出力、条件を明示する。
- 「適切に」「十分に」「効率的に」「柔軟に」など、基準が必要な語には基準や観測方法を添える。
- 「ユーザー」「システム」「データ」のように広すぎる語は、誰、どのコンポーネント、どのデータかへ具体化する。

専門用語を減らすことが常に親切とは限らない。
同僚向けの文書では定着した用語を使い、初学者向けでは用語の役割と具体例を添える。

## 情報を残すか迷ったときの例

共通本文の目的と情報の優先順位に照らして判断する。
表現の形だけで削除を決めない。

| 省く候補 | 残す候補 |
| --- | --- |
| 運用担当者向けの文で、既知の「デプロイ」に「本番への反映」と和訳を重ねる | 初めて操作する読者に、未知で必要な用語を初出で説明する |
| 同じ主張を直後に言い換える文 | 長い説明の後で、読者が判断を思い出すための短い再提示 |
| 主題と関係しない一般論 | 結論が成立する条件や、操作に必要な前提 |
| 内容を増やさない括弧の言い換え | 「処理時間は12秒から7秒になった」のような比較値、適用条件、出典 |

## 段落と並列を整える

- 段落の冒頭で、その段落が答える問いまたは進める論点を示す。
- 一つの段落に、背景、結論、例外、次の行動を詰め込まない。役割が変わるところで分ける。
- 箇条書きの項目は、同じ比較軸と文法で始める。項目の中に別の論点を隠さない。
- 接続詞は、前後の論理関係を読者が誤る場合だけ置く。「また」「一方」「つまり」を段落の習慣として置かない。
- 同じ語尾や構文が続く場合は、意味の違いを明確にしたうえで必要な箇所だけ変える。変化を作るために曖昧な表現へ逃げない。

## 不自然さを診断する

次の兆候があれば、単語の置換ではなく、元の主張と関係を確認する。

- 冒頭が一般論や意気込みだけで始まり、対象と結論が後ろに隠れている。
- 「重要です」「可能です」「有効です」などの評価だけがあり、何に対してなぜそう言えるかがない。
- すべての節が同じ長さ、同じ三項構成、同じ語尾で、重要度の差が見えない。
- 「つまり」「要するに」「このように」が、直前の内容を追加せず繰り返している。
- 「AではなくB」が多いが、Aが実際の誤解や対立候補になっていない。
- 人間の判断、失敗、迷い、時系列などの意味を、均一で抽象的な文へ置き換えている。

不自然さを直すときは、まず不要な文を削る。
次に対象、動作、理由、条件を具体化する。
それでも必要なら、文の順序や段落の役割を組み替える。
定型句を別の定型句へ置き換えるだけの修正は避ける。

## 最終確認

- 音読または一度だけの流し読みで、主語、述語、条件、結論を見失わないか。
- 文を短くした結果、否定、数量、期限、適用範囲、確度が変わっていないか。
- 「かもしれない」「推測できる」「確認した」などの確度が、根拠に対応しているか。
- 見出しと本文の語が一致し、読者が検索しやすいか。
- 書き手の都合のよい順序ではなく、想定読者が知っている順序と必要な順序になっているか。
