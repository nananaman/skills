# MISSION.md の形式

`MISSION.md` は作業領域の直下に置く。ユーザーがこのテーマを学ぶ理由を短く固定し、何を教えるか、どの資料を選ぶか、どの練習を作るかの判断基準にする。

## テンプレート

```md
# 学習目的：{テーマ}

## 学ぶ理由
{1-3 文。ユーザーが追っている現実の目標。これを身につけると仕事・生活・制作物がどう変わるか。"X を理解する" のような抽象表現は避け、背後の成果まで掘る。}

## 成功条件
- {観察可能な到達状態}
- {別の到達状態}
- {…}

## 制約
- {時間、予算、締切、前提知識、学習スタイルなど}

## 対象外
- {今は追わない隣接トピック。近接発達領域を守るために書く}
```

## 規則

- **一つの作業領域には一つの学習目的だけを置く。** 無関係なテーマを同じ作業領域に混ぜない。
- **具体を優先する。** 「健康になる」より「10 月までにハーフマラソンを走る」。「Rust を学ぶ」より「チーム向け Rust CLI を出荷する」。
- **曖昧なら質問する。** 曖昧な目的は、目的がない状態より危険である。すぐに授業を作らず、目的を聞き取る。
- **変化したら更新する。** 学習目的が変わったら古いままにしない。必要なら学習記録にも残す。
- **短く保つ。** 一画面を超えるなら、判断の基準ではなく計画になっている。
