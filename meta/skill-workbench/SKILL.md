# Skill の作成・改善とレビュー

skill がユーザーの成果を安定して達成できるかを評価する。既存の手順や停止条件の維持、確認項目の消化を目的にしない。

## 作業の振り分け

| 依頼 | 作業と読む資料 |
| --- | --- |
| 改善提案 | 本文と必要な近接skillを調べ、改訂案・理由・確認方法を返す。編集はしない。[設計原則](references/design-principles.md) |
| 新規作成・改善 | 要求と起動条件を確かめて変更し、その変更に必要なレビューを行う。[設計原則](references/design-principles.md) |
| 差分レビュー | 変更された指示と必要な周辺情報を評価する。[レビュー手順](references/review-protocol.md) |
| 全体レビュー | 対象skillの成果、本文の制約、振り分け、参照先を評価する。[レビュー手順](references/review-protocol.md) |
| 一覧の監査 | 複数skillの連鎖、重複、停止条件、通常経路の負荷を調べる。[監査手順](references/audit-protocol.md) |

skill本文の過剰制約の指摘も、このskillのレビュー範囲である。別のprompt診断や保存対象表の完成を前提にしない。
モデル固有のprompt改訂が必要なら `improve-agent-prompt` を併用できる。外部資料の比較や実行型評価が判断に必要な場合だけ、[根拠の比較](references/evidence-synthesis.md) または [評価手順](references/eval-loop.md) を読む。

## 作成と改善

ユーザーの成果、起動する条件、領域固有の制約、必要な検証を定める。安全に調べられる情報は既存の正本やコードから取得する。
保存する要求は、ユーザーの指示、業務・安全・権限の境界、外部の利用者やツールの依存から決める。
既存の承認、完了条件、出力項目、参照の必須化は必要性を評価し、削除・限定・統合・配置変更の候補にする。

- `SKILL.md` は成果と判断に必要な入口にし、一部の作業だけに必要な詳細を参照資料へ分ける。
- description は起動前に使う振り分け情報にする。責務が変わる場合は近接skill、README、agentメタデータの導線も揃える。
- 共通の承認・進捗・文体規則は、実際に適用される上位指示との重複を避ける。単独で配布・利用する場合は、その環境でも必要な前提が得られるか確認する。
- 探索順序や固定回数は、領域固有の失敗を防ぐ根拠がある場合に限る。重要な安全境界とユーザーの明示要求は弱めない。
- 正本を編集し、commit、push、APM更新、installは、その操作が依頼された場合だけ行う。

## レビュー範囲

差分レビューを既定にする。新規skill、責務・権限境界・主要な完了条件の変更、または差分だけでは原因を評価できない問題は全体を見る。
全体レビュー後の修正確認は、影響した指示と参照先に絞る。指摘修正だけを理由に全手順を最初から繰り返さない。

本文が短い、参照先へ分離した、既存規則を保存した、という事実だけでは合格にしない。
自然な依頼に対して、許可済みの作業を進められるか、不要な質問・レビュー・報告を増やさないかを評価する。
静的な読解で解けない重要な疑問がある場合は、その疑問に必要な動作確認を選ぶ。

## 権限と報告

依頼・会話内の許可と上位の実行制約に従う。レビューや提案だけの依頼では編集しない。
一部の情報が不足しても、根拠のある指摘や改訂案は返す。不足に依存する操作だけを保留し、未実施の確認を成功扱いにしない。

結果、根拠のある指摘または変更、実施した確認、残る不確実性を報告する。
詳細な台帳は追跡が必要な場合だけ使い、選ばなかった全評価軸や同じ根拠を機械的に列挙しない。
